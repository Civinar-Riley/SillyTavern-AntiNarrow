# 窄化根因与修复原理

> 本文基于 SillyTavern 公开仓库 `public/style.css` / `public/index.html`（2025-10 版本）的逐行核对，行号供定位参考，随版本漂移。

## 1. 现象

移动端（以及 PC 窄聊天列时）渲染出来的整页 HTML——开场页闸门、正文美化卡、任何酒馆助手 iframe——只占屏幕中间一条窄带（实测 1080px 截图里约 642px，≈59%），两侧露出聊天背景。有人称之为"边框窄化"。

## 2. 根因：宿主消息行的固定 insets，不是页面的 CSS

iframe 页面本身是 `width:100%` 填满 `.mes_text` 的，问题在于 `.mes_text` 的可用宽度被宿主逐层扣掉：

| 来源 | 元素 | 尺寸 | 出处（style.css） |
|---|---|---|---|
| 聊天列宽 | `#sheld` | `var(--sheldWidth)`，默认 `50vw`，主题字段 `chat_width` 可调（25~100，默认 55） | :92、:772 |
| 消息行内边距 | `.mes` | `padding: 10px 10px 0 10px` | :1185 |
| 头像列 | `.mesAvatarWrapper` | `--avatar-base-width: 50px` | :121 |
| 名字栏缩进 | `.mes_block` | `padding-left: 10px` | :1511 |
| 正文右缘 | `.mes_text` | `padding-right: var(--mes-right-spacing)` = 30px | :120、:1527 |
| 思考块 | `.mes_reasoning_details` | `margin-right: 30px`（摘要行 `-30px` 负边距抵消） | :436、:441 |
| 媒体行 | `.mes .mes_media_wrapper` | `padding-right: 30px` | :5177 |

合计约 **90~100px**（头像列 + 三个 10px + 30px，视头像设置而定）。在 412px 手机视口、聊天列 85vw 时，可用宽度只剩约 60%。

`#chat` 本体没有横向 padding（移动端只有 border）；`--mes-right-spacing` 的 30px **不是**给 `.mes_buttons` 预留的——按钮挂在 `.ch_name` 行内（`index.html` 消息模板 `.mes > .mes_block > .ch_name > .mes_buttons`），常驻显示、透明度 0.3。

### 为什么闸门页看起来"只有中间一条是页面"

入场闸门封面是 `position: fixed; inset: 0`，`fixed` 在 iframe 内以 **iframe 视口**为基准，所以近不透明的封面把 iframe 填满，深色窄柱就是 iframe 的真实边界——它正是被上表扣出来的。

## 3. 修复思路：把被扣掉的宽度还回去

页面在 iframe 里本来就是 100% 宽，所以要做的只有两件事，都在**宿主侧**：

1. **CSS 清零**：`.mes` / `.mes_block` / `.mes_text` 的内边距清零（含思考块与媒体行的 30px 同源缩进，负边距成对处理），内容即铺满整条聊天列。
2. **头像搬行**：头像列是 flex 行里独占的 50px 竖列，把它搬进 `.ch_name`（名字栏）显示，消息行让出整列。社区里沉浸类布局脚本用的正是同一套思路。

只做清零不做头像处理，宽度收益少约 50px；只搬头像不清零，正文仍被三个 10px/30px 的预留位挤压。本脚本两者都做，且各自可配置。

## 4. 本脚本的实现要点

- **清零**：`.mes` / `.mes_block` / `.mes_text` 内边距清零；思考块 `margin-right` 与摘要行负边距、媒体行 `padding-right` 成对清零（只清外层会让摘要行冲出右边缘）。`.mes_buttons` 的原生位置与这些预留位无关；搬移后的网格仅调整其分行和收缩规则。
- **左右留白**：用 `margin` 而非 padding 内缩 `.mes`（`width: calc(100% - 2*pad)`）——margin 不参与 `width:100%` 的 content-box 计算，避免右侧溢出被裁导致左右不对称。
- **头像搬移**：`chName.insertBefore(av, chName.firstChild)` + `data-mt-antinarrow-moved` 标记。名字栏改为两行网格，头像跨两行、名字与操作按钮居首行，楼层 / 计时 / token 在次行横排；三项原节点收进头像列内的 `.mtan-message-meta`，头像列用 `display:contents` 参与网格，原生末楼 padding 不再撑高名字栏。数据仍由酒馆更新，显隐沿用原生开关；空项不占位，窄处按整项换行。还原时解开信息容器并放回头像列。防重复：只搬 `.mes` 直接子列的头像，已被任何脚本搬进名字栏的一律跳过。
- **重roll条**：头像列搬移或收起后，不再依赖头像高度补底部空带。按 `.swipes_visible` / `.last_swipe`、控件 `[hidden]`、`body.hideAllSwipeButtons` 和 `body.swipeAllMessages` 判断需要的空间；默认尺寸下无控件为 0px、仅计数器为 24px、有箭头为 49px。箭头占 25px，计数器高度和下边距来自 `--swipeCounterHeight` / `--swipeCounterMargin`，另加 4px 间隔。小型系统消息和原生沉浸布局不参与补偿。
- **维持与还原**：MutationObserver（`#chat` childList+subtree）+ `tavern_events.CHAT_CHANGED` 维持新楼层——观察器只认新增消息行、含消息行的容器与被插回消息行直接子级的头像列，流式正文更新不触发全量扫描。已搬到位的节点不重复还原和搬移，留白、消息头疏密等设置只改样式。`pagehide` 按实例标记还原头像、断开观察器、移除样式，并显式调用每个 `eventOn` 返回句柄的 `stop()`。
- **设置面板**：脚本按钮或悬浮齿轮开关，关闭按钮、点外和 Esc 收起；只抑制同一次外点手势的后续 click，下一次点击可立即打开。面板使用 dialog 语义、选项同步 `aria-pressed`，开关时管理焦点；显示当前生效状态。位置使用实际 `#sheld` 边界与 `visualViewport` 可见范围计算，避免原生手机宽度与 `--sheldWidth` 不同造成偏移。断点输入只在合法范围内防抖提交，配置仍保存在原 localStorage key。
- **拉满全屏**：`:root{--sheldWidth:100vw}` 连变量一起覆盖，`#sheld` 的 `left:0;right:0;margin:0 auto` 自动居中；其余顶部抽屉 `.drawer-content` 宽度即 `var(--sheldWidth)`（:5555 起），随之全屏。但**左右导航抽屉** `#left-nav-panel`/`#right-nav-panel`（类 `.fillLeft`/`.fillRight`，:5622-5647）与浮层 `#floatingPrompt`/`#cfgConfig`（:2960-2973）的原生宽度是「两侧空隙的一半」`calc((100dvw - var(--sheldWidth) - 2px)/2)`，拉满后算式为负、塌缩成 `min-width:100px`（:5612 的 `!important` 保底）窄条——脚本照移动端做法（`mobile-styles.css` 把抽屉全屏化）补 `width:100dvw` 全屏展开，并显式锚定 `left:0`/`right:0`（`.fillRight` 原生 `left` 是一处 `+1px` 缺空格的非法 calc，实际定位一直由 `right:0` 决定；显式锚定后也不受其未来修复影响）。同时 `top` 下移到 `var(--topBarBlockSize)` 让出顶栏图标行：抽屉面板与开关图标同为 `#top-settings-holder`（z-index:3005）的后代，面板 `fixed top:0 z:3000` 会盖住无定位的图标，而酒馆关闭抽屉只有「再点开关图标」（`doNavbarIconClick`）与「点击抽屉以外区域」（:12182 自动收起）两条路，盖住顶栏后两条路全断、抽屉永远关不掉——移动端同样让出顶栏（`top:0` + `margin-top:36px`）；脚本注入 `margin-top:0!important` 抵消移动端另叠的 `margin-top:36px`，避免 top+margin 双重偏移让面板上方漏出空隙。同款塌缩还有两处（v1.2.1 收口）：`#logprobsViewer` 在 `css/logprobs.css`（:19）自带 `width: calc((100dvw - var(--sheldWidth))/2 - 1px)`、`min-width:100px`，并入浮层的宽度规则即可；**头像放大视图** `.zoomed_avatar` 由 `script.js`（:12258）运行时挂 `.draggable` 类，吃 `.draggable`（:5860）的同款宽度公式塌成 100px，且 `--leftGapWidth: calc((100vw - var(--sheldWidth))/2)`（:5885）归零后 `left: var(--leftPosition)` 把它钉在左缘——脚本覆盖 `--leftGapWidth:100dvw` 让原生居中公式自行在整屏内生效、宽度补回 `var(--maxWidth)`（90vh×0.666）自然值，但只放进 `@media (min-width:1001px)`：酒馆移动端块（:6092 起，`max-width:1000px`）自带 `.draggable{width:100vw;height:100vh}` 全屏展开（:6093），窄视口不能覆盖它。其余 `--sheldWidth` 消费方（`.bg_list`、`#top-bar`、`#top-settings-holder`、`.drawer-content`、`wide_dialogue_popup` 的 `min-width`、各处 `max-width`）拉满后或无害或本就是全屏意图，无需处理。
- **窄屏 = DOM 与 CSS 同步**：「仅窄屏」不只把 CSS 包进 `@media`——头像搬移用宿主 `matchMedia('(max-width:断点)')` 判定（`moveAvatars` 守卫，脚本 iframe 的视口不是真实窗口），并监听 `change` 在跨断点时自动搬/还原（`narrowOnly`/断点变更时重建监听）。否则桌面端会搬走头像而补偿 CSS 不生效，末楼名字栏被原生 50px 预留撑出空带。
- **生命周期防护**：宿主 `__mtAntinarrowCleanup` 保存活动实例的清理函数，新实例先完整停止旧实例再接管。清理幂等，所有延时回调检查 stopped；头像搬移标记和注入节点均记录实例令牌，迟到的旧 pagehide 不会触碰新实例。定时器、媒体查询、宿主事件、消息/设置按钮订阅全部显式卸载。搬家防抖仍用 setTimeout，避免隐藏 iframe 的 rAF 不触发。
- **看门狗**：`head` 的 MutationObserver（防抖 200ms）自查布局规则是否仍在 `head` 末尾——之后出现别的 `<style>`/样式表 `<link>`（被盖住）、本脚本样式被整个删除或挪出 `head`、UI 样式被删，都算失守并触发恢复：样式节点还在就 append 挪回末尾，没了就 `injectStyles()` 整体重建（UI 样式一并补回）。所有规则本就 `!important`，同优先级规则比顺序，看门狗保证晚加载的主题/其他沉浸脚本盖不掉本脚本（`.mes`/`.mes_text` 的宽度声明也已补 `!important`，防主题改写后窄化复发）。
- **急救暂停**：面板「注入」行切到「暂停」即清空布局 CSS 并还原头像；暂停时仍维护面板 UI 样式，被删除后可重建。
- **阅读与消息头**：`columnMode` 分为 native / reading / full，旧 `widenColumn` 设置在读入时映射为 full 或 native。reading 使用 `min(100dvw,上限)` 同步 `#sheld` 和宽度变量。头像放大修复与布局一起受窄屏范围约束。消息头标准档保留头像原尺寸，紧凑档上限36px；文档模式和小型系统消息不搬移，隐藏头像时折叠空列，展开操作和编辑按钮使用独立行。

## 5. 逐项核对过的关键事实

- `--avatar-base-height/width` 默认 **50px**（:120-123）；swipe 底部空带唯一来源就是 `.last_mes .mesAvatarWrapper` 的 padding-bottom（全仓库仅此一处引用）。
- `.swipe_left` 显式 `left: 20px`（:1315）；`.swipeRightBlock { right:0; bottom:0 }`；swipe DOM 每楼都渲染，默认只显示末楼，开启 `swipeAllMessages` 后旧楼也可显示；箭头由 `swipes_visible` / `last_swipe` 和隐藏属性决定。
- `#chat` 无横向 padding；移动端有 border（`mobile-styles.css`）。
- 左右导航抽屉在现代 ST 里是 `#left-nav-panel.fillLeft` / `#right-nav-panel.fillRight`（`index.html` :72、:6006），宽度来自聊天列两侧空隙而非 `var(--sheldWidth)`，且 `.fillRight` 的 `left: calc(100% - var(--sheldWidth) /2 + var(--sheldWidth) +1px)` 因 `+1px` 缺空格整条声明非法，定位实际由 `right:0` 生效——这就是拉满全屏时两抽屉塌缩、其余抽屉正常的根因。抽屉的关闭路径只有两条：开关图标再点一次（`doNavbarIconClick`）与点击抽屉以外区域自动收起（`script.js` :12182）；面板与图标同为 `#top-settings-holder` 后代、面板 `fixed top:0 z:3000` 而图标无定位，全屏后图标被盖、屏幕上再无「外部」可点——脚本因此把面板 `top` 下移到 `var(--topBarBlockSize)` 让出顶栏图标行。
- 酒馆助手脚本跑在隐藏 iframe，宿主文档必须 `window.parent.document`；`$(() => {})` 替代 DOMContentLoaded；`$(window).on('pagehide')` 是官方停用钩子；`getCurrentMessageId()` 仅楼层 iframe 可用。
- 酒馆助手脚本按钮：编辑页「按钮」区声明，代码 `eventOn(getButtonEvent('按钮名'))` 监听，`appendInexistentScriptButtons` 可自注册。
