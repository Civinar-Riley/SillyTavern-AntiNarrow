# 窄化根因与修复原理

> 本文基于 SillyTavern 公开仓库 `public/style.css` / `public/index.html`（2025-10 版本）的逐行核对，行号供定位参考，随版本漂移。

## 1. 现象

移动端（以及 PC 窄聊天列时）渲染出来的整页 HTML——开场页闸门、正文美化卡、任何酒馆助手 iframe——只占屏幕中间一条窄带（实测 1080px 截图里约 642px，≈59%），两侧露出聊天背景。有人称之为"边框窄化"。

## 2. 根因：宿主消息行的固定 insets，不是页面的 CSS

iframe 页面本身是 `width:100%` 填满 `.mes_text` 的，问题在于 `.mes_text` 的可用宽度被宿主逐层扣掉：

| 来源 | 元素 | 尺寸 | 出处（style.css） |
|---|---|---|---|
| 聊天列宽 | `#sheld` | `var(--sheldWidth)`，默认 `50vw`，主题字段 `chat_width` 可调（25~100，默认 55） | :92、:772 |
| 消息行内边距 | `.mes` | `padding: 10px 10px 0 10px` | :1185 |
| 头像列 | `.mesAvatarWrapper` | `--avatar-base-width: 50px` | :121 |
| 名字栏缩进 | `.mes_block` | `padding-left: 10px` | :1511 |
| 正文右缘 | `.mes_text` | `padding-right: var(--mes-right-spacing)` = 30px | :120、:1527 |
| 思考块 | `.mes_reasoning_details` | `margin-right: 30px`（摘要行 `-30px` 负边距抵消） | :436、:441 |
| 媒体行 | `.mes .mes_media_wrapper` | `padding-right: 30px` | :5177 |

合计约 **90~100px**（头像列 + 三个 10px + 30px，视头像设置而定）。在 412px 手机视口、聊天列 85vw 时，可用宽度只剩约 60%。

`#chat` 本体没有横向 padding（移动端只有 border）；`--mes-right-spacing` 的 30px **不是**给 `.mes_buttons` 预留的——按钮挂在 `.ch_name` 行内（`index.html` 消息模板 `.mes > .mes_block > .ch_name > .mes_buttons`），常驻显示、透明度 0.3。

### 为什么闸门页看起来"只有中间一条是页面"

入场闸门封面是 `position: fixed; inset: 0`，`fixed` 在 iframe 内以 **iframe 视口**为基准，所以近不透明的封面把 iframe 填满，深色窄柱就是 iframe 的真实边界——它正是被上表扣出来的。

## 3. 修复思路：把被扣掉的宽度还回去

页面在 iframe 里本来就是 100% 宽，所以要做的只有两件事，都在**宿主侧**：

1. **CSS 清零**：`.mes` / `.mes_block` / `.mes_text` 的内边距清零（含思考块与媒体行的 30px 同源缩进，负边距成对处理），内容即铺满整条聊天列。
2. **头像搬行**：头像列是 flex 行里独占的 50px 竖列，把它搬进 `.ch_name`（楼层数字栏）显示，消息行让出整列。社区里沉浸类布局脚本用的正是同一套思路。

只做清零不做头像处理，宽度收益少约 50px；只搬头像不清零，正文仍被三个 10px/30px 的预留位挤压。本脚本两者都做，且各自可配置。

## 4. 本脚本的实现要点

- **清零**：`.mes` / `.mes_block` / `.mes_text` 内边距清零；思考块 `margin-right` 与摘要行负边距、媒体行 `padding-right` 成对清零（只清外层会让摘要行冲出右边缘）。`.mes_buttons` **不需要处理**——原生就在名字行，与这些预留位无关。
- **左右留白**：用 `margin` 而非 padding 内缩 `.mes`（`width: calc(100% - 2*pad)`）——margin 不参与 `width:100%` 的 content-box 计算，避免右侧溢出被裁导致左右不对称。
- **头像搬移**：`chName.insertBefore(av, chName.firstChild)` + `data-mt-antinarrow-moved` 标记；搬家后必须清掉跟随节点的 `.last_mes .mesAvatarWrapper { padding-bottom: var(--avatar-base-height) }`（50px），否则名字栏被撑高。防重复：只搬 `.mes` 直接子列的头像，已被任何脚本搬进名字栏的一律跳过。
- **重roll条**：原生 `‹ ›` 的底部空带唯一来源是 `.last_mes .mesAvatarWrapper { padding-bottom: var(--avatar-base-height) }`（:1415）。头像一旦离开消息行（搬移或隐藏），空带消失，按钮叠在正文上。修复：给 `#chat .mes.last_mes` 补 `padding-bottom: calc(var(--avatar-base-height,50px) + 4px)`；`.swipe_left` 自带 `left:20px`、`.swipeRightBlock` 贴 `right:0`，落在空带内。`body:not(.immersive-mode)` 前缀：宿主已开启沉浸类布局（自带导航按钮）时自动让位，避免双重预留。
- **维持与还原**：MutationObserver（`#chat` childList+subtree）+ `tavern_events.CHAT_CHANGED` 维持新楼层；`pagehide`（官方脚本停用钩子）按标记还原头像、断开观察器、移除样式。`eventOn` 监听由酒馆助手自动卸载。
- **设置面板**：由脚本按钮「防窄化设置」（`getButtonEvent` + `appendInexistentScriptButtons` 自注册）开关；配置持久化在 localStorage `mtAntiNarrow.settings.v1`；CSS 文本随设置重建，`narrowOnly` 时整体包进 `@media`。
- **拉满全屏**：`:root{--sheldWidth:100vw}` 连变量一起覆盖，`#sheld` 的 `left:0;right:0;margin:0 auto` 自动居中；其余顶部抽屉 `.drawer-content` 宽度即 `var(--sheldWidth)`（:5555 起），随之全屏。但**左右导航抽屉** `#left-nav-panel`/`#right-nav-panel`（类 `.fillLeft`/`.fillRight`，:5622-5647）与浮层 `#floatingPrompt`/`#cfgConfig`（:2960-2973）的原生宽度是「两侧空隙的一半」`calc((100dvw - var(--sheldWidth) - 2px)/2)`，拉满后算式为负、塌缩成 `min-width:100px`（:5612 的 `!important` 保底）窄条——脚本照移动端做法（`mobile-styles.css` 把抽屉全屏化）补 `width:100dvw` 全屏展开，并显式锚定 `left:0`/`right:0`（`.fillRight` 原生 `left` 是一处 `+1px` 缺空格的非法 calc，实际定位一直由 `right:0` 决定；显式锚定后也不受其未来修复影响）。同时 `top` 下移到 `var(--topBarBlockSize)` 让出顶栏图标行：抽屉面板与开关图标同为 `#top-settings-holder`（z-index:3005）的后代，面板 `fixed top:0 z:3000` 会盖住无定位的图标，而酒馆关闭抽屉只有「再点开关图标」（`doNavbarIconClick`）与「点击抽屉以外区域」（:12182 自动收起）两条路，盖住顶栏后两条路全断、抽屉永远关不掉——移动端同样让出顶栏（`top:0` + `margin-top:36px`）；脚本注入 `margin-top:0!important` 抵消移动端另叠的 `margin-top:36px`，避免 top+margin 双重偏移让面板上方漏出空隙。
- **窄屏 = DOM 与 CSS 同步**：「仅窄屏」不只把 CSS 包进 `@media`——头像搬移用宿主 `matchMedia('(max-width:断点)')` 判定（`moveAvatars` 守卫，脚本 iframe 的视口不是真实窗口），并监听 `change` 在跨断点时自动搬/还原（`narrowOnly`/断点变更时重建监听）。否则桌面端会搬走头像而补偿 CSS 不生效，末楼名字栏被原生 50px 预留撑出空带。
- **生命周期防护**：注入节点（样式×2/齿轮/面板）带实例令牌 `data-mtan-owner`，停用钩子只拆自己的节点——热重载/双开时旧实例迟到的 `pagehide` 不再拆掉新实例的样式与面板；`whenChat` 轮询、`CHAT_CHANGED` 兜底延时、搬家防抖、看门狗防抖全部登记并在 cleanup 清除（旧版在 #chat 出现前停用脚本，轮询存活会“复活”搬移）；搬家防抖用 `setTimeout` 而非 rAF（隐藏 iframe 的 rAF 可能永不触发，防抖标记会永久卡死）。
- **看门狗**：`head` 的 MutationObserver（防抖 200ms）发现本脚本 `<style>` 之后又出现别的 `<style>`/样式表 `<link>` 时，把样式标签重新 append 到 head 末尾——所有规则本就 `!important`，同优先级规则比顺序，看门狗保证晚加载的主题/其他沉浸脚本盖不掉本脚本（`.mes`/`.mes_text` 的宽度声明也已补 `!important`，防主题改写后窄化复发）。
- **急救暂停**：面板「注入」行切到「暂停」即清空注入 CSS 并还原头像（搬移守卫同步跳过），用于一键排查“是不是本脚本和其他美化冲突”；面板 UI 样式不受影响，随时可切回。

## 5. 逐项核对过的关键事实

- `--avatar-base-height/width` 默认 **50px**（:120-123）；swipe 底部空带唯一来源就是 `.last_mes .mesAvatarWrapper` 的 padding-bottom（全仓库仅此一处引用）。
- `.swipe_left` 显式 `left: 20px`（:1315）；`.swipeRightBlock { right:0; bottom:0 }`；swipe DOM 每楼都渲染，仅末楼显示（:1351 起 + `script.js` 的 `swipes_visible` 类）。
- `#chat` 无横向 padding；移动端有 border（`mobile-styles.css`）。
- 左右导航抽屉在现代 ST 里是 `#left-nav-panel.fillLeft` / `#right-nav-panel.fillRight`（`index.html` :72、:6006），宽度来自聊天列两侧空隙而非 `var(--sheldWidth)`，且 `.fillRight` 的 `left: calc(100% - var(--sheldWidth) /2 + var(--sheldWidth) +1px)` 因 `+1px` 缺空格整条声明非法，定位实际由 `right:0` 生效——这就是拉满全屏时两抽屉塌缩、其余抽屉正常的根因。抽屉的关闭路径只有两条：开关图标再点一次（`doNavbarIconClick`）与点击抽屉以外区域自动收起（`script.js` :12182）；面板与图标同为 `#top-settings-holder` 后代、面板 `fixed top:0 z:3000` 而图标无定位，全屏后图标被盖、屏幕上再无「外部」可点——脚本因此把面板 `top` 下移到 `var(--topBarBlockSize)` 让出顶栏图标行。
- 酒馆助手脚本跑在隐藏 iframe，宿主文档必须 `window.parent.document`；`$(() => {})` 替代 DOMContentLoaded；`$(window).on('pagehide')` 是官方停用钩子；`getCurrentMessageId()` 仅楼层 iframe 可用。
- 酒馆助手脚本按钮：编辑页「按钮」区声明，代码 `eventOn(getButtonEvent('按钮名'))` 监听，`appendInexistentScriptButtons` 可自注册。
